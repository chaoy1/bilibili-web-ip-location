# 安装说明

> 适用：华为浏览器 PC 版 12.1.4.300（Chromium 99 内核，Windows）
> 其它 Chromium 内核浏览器操作完全相同，只是扩展管理页地址可能不同。

整个过程大约 1 分钟。**不需要联网下载任何插件**，只是让浏览器读取本地这个文件夹。

---

## 一、先拿到代码

```bash
git clone https://github.com/chaoy1/bilibili-web-ip-location.git
```

或者在仓库页面点 **Code → Download ZIP** 后解压。

> ⚠️ 注意分清两个名字：
> 仓库叫 **`bilibili-web-ip-location`**，而下面**第四步**要选的是它**里面**的
> **`bilibili-ip-location`** 子文件夹。

## 二、打开扩展管理页

1. 打开浏览器。
2. 在地址栏输入下面这一行，按回车：

   ```
   chrome://extensions
   ```

3. 页面标题会显示「**扩展程序**」，这就是扩展管理页。

> 如果 `chrome://extensions` 被拦下来跳到了搜索页，试试 `huawei://extensions`。
> 这两个地址在华为浏览器上都已验证可用。

## 三、打开「开发者模式」

页面**右上角**有一个「**开发者模式**」开关，把它打开。

打开之后，左上角会多出三个按钮：`加载已解压的扩展程序` / `打包扩展程序` / `更新`。

> 如果没看到这三个按钮，说明开发者模式没打开成功，再点一次开关。

## 四、加载扩展

1. 点左上角的「**加载已解压的扩展程序**」。
2. 在弹出的文件夹选择框里，选中仓库里的 **`bilibili-ip-location`** 子文件夹，
   然后点「选择文件夹」。

   ⚠️ **要选中 `bilibili-ip-location` 这个文件夹本身**。
   不要选到仓库根目录（那是 `bilibili-web-ip-location`），也不要进到 `src` 里面去 ——
   浏览器需要在这个文件夹的第一层直接看到 `manifest.json`。

3. 加载成功后，列表里会出现一张卡片：**「B站评论 IP 属地」**，版本 `1.0.0`。

## 五、去 B 站验证

1. **先确认你已经登录 B 站账号。**
   这是最关键的一步：B 站的评论接口只在**携带登录 Cookie** 的请求里才返回 IP 属地字段，
   未登录时该字段是空的，插件无从显示。
2. 打开任意一个视频页（例如 `https://www.bilibili.com/video/BV1GahD6GEjC/`），往下滚到评论区。
3. 每条评论的**等级徽章右边**，就会直接显示 IP 属地（纯文字，没有底色/边框）：

   ```
   云启天青  Lv5  IP属地：广东  博士博士
   ```

主评论和「点击查看」展开的子回复都会显示。

## 六、常见问题

**Q：完全不出现 / 刷新后不见了**
- 打开 `chrome://extensions`，确认「B站评论 IP 属地」的开关是**蓝色启用**状态。
- 点该卡片上的**刷新图标**（🔄）重新加载扩展，然后回到 B 站按 `F5`。
- 确认浏览器**没有处于无痕/隐私模式**（无痕模式下扩展默认不生效，需要在扩展详情里单独勾选「在无痕模式下启用」）。
- 确认**已登录 B 站**（见上一节第 1 条）。

**Q：评论区显示「登录后查看 3000+ 条评论」**
- 说明你没登录 B 站。未登录时 B 站本身只放行少量评论，且接口不返回属地。登录后即可。

**Q：有些评论没有属地**
这是正常的，不是插件的问题：
- B 站 **2022 年 7 月上线 IP 属地功能之前**发布的老评论，接口里根本没有这个字段。
- 部分场景（如转发动态、部分专栏/活动页）B 站接口不返回属地，插件就无从显示。
- 部分账号的设置不公开属地。

**Q：我改了代码，怎么生效？**
到 `chrome://extensions` 点这张卡片上的**刷新图标**，再刷新 B 站页面。
改 `src/` 下的代码需要点刷新；改 `manifest.json` **必须**点刷新。

**Q：怎么卸载？**
在 `chrome://extensions` 里点该卡片的「移除」。

## 七、它做了什么（简述）

1. 页面加载时，插件把一个很小的钩子脚本注入到 B 站网页自己的 JS 环境里，
   监听网页**自己**对 `api.bilibili.com/x/v2/reply*` 的请求，从响应里读出
   `reply_control.location`（形如 `IP属地：上海`）以及对应的用户 `mid`。
2. 因为评论区是 Web Component + Shadow DOM 结构，脚本会**递归穿透每一层 Shadow DOM**，
   找到每条评论的等级徽章，把属地插到它右边。
3. 全程只读不写，不修改 B 站的任何请求或响应，也不向任何第三方服务器发送数据。

详细原理见项目根目录的 [README.md](../README.md)。
